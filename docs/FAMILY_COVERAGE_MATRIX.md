# AG32 family coverage matrix

Generated by `tools/generate_family_coverage_matrix.py` from `agamemnon/sdk/family_coverage_matrix.json`; do not edit by hand.

Rows are the seven AG32 family part numbers (`tools/AG32_RefManual.txt` Sec 1.2, transcribed in `agamemnon/engine/family.py`); columns are the surfaces `GOAL_AG32_FAMILY_COVERAGE.md` tracks. **Building for a part is never a silicon claim for that part** -- a fabric-logic-only build (`build-supported`) works family-wide because the AGRV2K fabric is identical across the family; a `silicon-qualified` cell requires a recorded, reviewed evidence trail on that exact physical part.

Campaign qualifier (2026-08-24): a `silicon-qualified` matrix cell means that
at least one exact subset exists on that part; it does not qualify every route
or mode in the cell. L48 now has both passing input/peripheral routes and
independent correctness escapes for new physical-input/SPI-MISO compositions.
See [STATUS.md](STATUS.md) for the exact subset. No campaign result changes the
absence of qualification on other parts/packages.

## Tiers

| Tier | Meaning |
|---|---|
| `silicon-qualified` | An approved, evidence-backed silicon claim exists for this exact part and surface (a physical board was exercised and reviewed). |
| `build-supported` | The engine can emit a release-strict image for this surface on this device with no board required -- the AGRV2K fabric is identical across the family, so a fabric-logic-only capability qualified on one part carries to every part. This is a build claim, never a silicon claim. |
| `recovered-only` | Chipdb/decode data exists (or is expected to exist) for this surface, but no release-strict build path is admitted yet, or the surface has not been decoded/exercised on this part. |
| `n/a` | This surface does not apply to this part (e.g. PSRAM on a non-VH part). |

## Standing notes

PREMISE (do not re-litigate): one AGRV2K fabric + RV32IMAFC core + boot ROM is shared family-wide; only package/flash/PSRAM/analog surround differs per part. Building for a part is never a silicon claim for that part -- a silicon claim is per-board and never auto-transfers by package or pin number, even between two parts sharing one package. AG32VF303CCT6 (AGRV2KL48) is the only silicon-qualified row: it is the reference dev board with years of qualification ledgers (docs/KNOWN_GOOD_HARDWARE.md, agamemnon/sdk/qualified_fabric_profiles.json). Every other part's config_accept is 'build-supported' rather than 'recovered-only' because claim_policy (T25, agamemnon/engine/claim_policy.py) now admits a pad-free, fabric-logic-only build for any package under release-strict -- physical/electrical surfaces (pad_out/pad_in/oe) remain qualified on AGRV2KL48 only and stay 'recovered-only' elsewhere. AG32VF407RGT6 (LQFP64) has an in-progress physical bring-up (qualification/l64_bringup_evidence.jsonl, tasks T21-T24): pad-free config-accept and an AHB transaction have been observed on real silicon, but the investigation is open (an AHB read-value mismatch is unresolved) and deliberately not yet claimed as qualified by that work itself -- this matrix keeps it 'build-supported' with a note rather than promoting an in-flight, self-described non-conclusion. That same evidence does NOT transfer to AG32VH303RCT6, the other LQFP64 part: package evidence never transfers by pin number, and it does not transfer between two different parts sharing one package either -- they are different physical dies. AG32VF407VGT6 (LQFP100) is Brian's second physical board (AG32-Docs memory), but no AGaMEMnon qualification evidence has been recorded for it yet; it is treated exactly like an unqualified part until evidence lands.
