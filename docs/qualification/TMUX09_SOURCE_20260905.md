# Corrected TMUX09 source-image qualification

The four bounded `build --uarch --qualified-bram-write` profiles now have source
image identities distinct from their retained checkpoint identities. Required
BRAM constant connections and corrected clock branches change the source images;
reproducing the old images would discard those corrections.

A paired SRAM experiment on AGRV2KL48 at HSE 8 MHz / SYSCLK 10 MHz compared each
new image against its retained reference twice. All 16 captures passed with
500/500 expected h0 samples each, and all three known-good controls passed.
The four cases cover both write polarities and both hold cases at one fixed
address with one observed output lane. Final reset was issued and custody
released; there were no flash writes. The record and exact image identities
are in `qualification/registered_bram_tmux9_source_silicon.json`.

Both INIT1 candidates were initially emitted under a private exact-module
research exception before silicon testing. Following that experiment, all four
sources were rebuilt using the normal public CLI, without that exception, and
matched the witnessed raw and compressed hashes. The initialized-source
admission requires the existing structure, route and device/clock checks;
source and final image hashes remain mandatory. Edited INIT, route, device,
Port-B output use and missing profile remain rejected. The existing checkpoint
identities and the refusal of old INIT1 checkpoint packing are unchanged.

This qualification does not cover inferred/general RAM writes, more addresses,
more observed data lanes, masks, other sites, dual-port behavior, collision
semantics, independent clocks, or timing closure. Installed SDK archive validation
and the larger release gates remain separate requirements.
