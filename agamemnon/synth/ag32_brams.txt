# memory_libmap library: map inferred Verilog memories -> the AGRV2K 9-Kbit block RAM (ALTA_BRAM9K).
# True dual-port (each port has shared read/write address) x18 = 512 words x 18 bits. memory_libmap emits
# $__ALTA_BRAM9K_, which ag32_brams_map.v turns into the ALTA_BRAM9K primitive. A one-port ROM/RAM uses
# port A; a two-port memory uses both recovered physical ports. Narrow x9/x4/x2/x1 modes are also admitted.
# rdwr = old: read returns the OLD memory content when reading+writing the same address same cycle. This
# is the common BRAM default and, crucially, lets an inferred single-port RAM (not just a ROM) map here --
# with `no_change` a read+write RAM falls through to a giant FF array. CAVEAT: the read-during-write policy
# is NOT yet silicon-verified. BRAM writes DO reach silicon (updated 2026-09-15): the open flow board-proved
# a genuine multi-bit x18 write over MCU -- 5 DataInA lanes {0,2,3,4,6} board-witnessed ({0,2,4} by an
# INIT=1->0 direct-output mutation, {3,6} by a two-word distinct-value readback) via the site-read profile's
# characterized DataIn ingress -- and the vendor flow board-proved a full 18-bit write (72/72) plus per-byte
# ByteEn masking -- so the silicon supports the whole write surface. Two things are still open in the OPEN
# flow: (1) ROUTING breadth -- only DataInA[0]/[2]/[4] ingress corridors are promoted in the emitter so far;
# {3,6} are board-witnessed but not yet promoted, and wider WRITE widths need the remaining DataIn ingress
# lanes. For wider READ: the high-byte lanes route+emit (a probe routes DataOutA[9]/[14] to distinct hrdata
# sinks via free routing -- corridors are NOT the blocker), but per-bit high-lane read-path CONDUCTION is
# unproven on silicon (DataOutA[14] was board-negative; per-bit BufMUX read path). That conduction, not a
# corridor, is what full 18-bit read needs; a fresh board test of an open-flow high-lane route would settle it.
# (2) narrow SUB-WORD windowing -- per-byte ByteEn masking is now NATIVELY EMITTED and board-proven: a
# constant-0 ByteEnA lane (CFG_KMUX pos-8 gnd tie; sel17=ByteEnA[0], sel26=ByteEnA[1]) is carried from
# qin_pack (AGM_BYTEEN_A_MASK) to bitgen behind opt-in AGAMEMNON_BRAM_BYTEEN; a natively-built A/B masked
# the low byte on silicon (obs 0x23->0x00), default builds byte-identical. Correct native narrow
# (x1/x2/x4/x9) sub-word writes still need the packer's DataIn sub-word window on top of ByteEn masking.
# The `old` vs `new`/`no_change` read-during-write collision policy is
# still unverified on hardware -- verify it when a read+write-same-cycle image is board-tested.
ram block $__ALTA_BRAM9K_ {
	# Maximum address width is for the narrowest mode.  x18 uses nine of
	# these bits (512 words); narrow modes use progressively more.  Declaring
	# this as 9 incorrectly told memory_libmap that a 512x2 RAM was too deep.
	abits 13;
	# The macro is physically 9 Kibit and supports narrower port modes.  Listing
	# only 18 made Yosys spill SERV's 512x2 register file into 1024 fabric FFs.
	# Keep the proven x18 mode and admit the narrow modes used by vendor SERV
	# netlists; memory_libmap pads the data port to the selected physical width.
	widths 1 2 4 9 18 per_port;
	cost 64;
	init any;
	port srsw "A" "B" {
		clock anyedge;
		clken;
		# Preserve all three synthesis choices: constraining this library to OLD
		# changes Yosys's shared-driver topology and makes the retained mixed-init
		# dual-port oracle un-packable.  The emitter does not claim those three
		# modes as silicon-equivalent.  qin_pack removes named read-first
		# emulation only for the uniform-init OLD-mode composition qualified on
		# silicon; every collision-mode claim outside it remains open.
		portoption "WRITEMODE" "OLD" { rdwr old; }
		portoption "WRITEMODE" "NEW" { rdwr new; }
		portoption "WRITEMODE" "NO_CHANGE" { rdwr no_change; }
		rdinit any;
	}
}
